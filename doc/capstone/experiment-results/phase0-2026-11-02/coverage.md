**Workload controls**

Environment options: `PHASE0_ROBOTS` comma-separated subset of the 8 existing robots (default host11); `PHASE0_DURATION=12`; `PHASE0_MOVE_INTERVAL=4`; `PHASE0_DISCONNECT=0`; `PHASE0_PROBE_RATE=10`; `PHASE0_SAMPLE_INTERVAL=0.5`; `PHASE0_REPETITIONS=1`; `PHASE0_SEED=0`; `PHASE0_SCHEDULE=synchronized|staggered`. Destinations alternate leaf1/leaf2; hosts starting on leaves3/4 first move to leaf1. The seed deterministically shuffles robot scheduling order. Repetitions mean move rounds within one topology, not statistically independent trials; use fresh pytest invocations for independent runs. All 8 robots remain attached and primed even when only one is selected for movement/probes; this is not configurable total active fleet size.

A synchronized round uses common scheduled deadlines but serialized namespace commands. It does not promise simultaneous link transitions. Staggering distributes deadlines over the move interval. Sampling can delay command issue; actual and scheduled times are recorded. Requested interval is not guaranteed realized movement rate. Disconnection pauses also pause snapshots, while independent probes and captures continue. Large fleets/long disconnect periods need a scheduler redesign before rate experiments.

`PHASE0_MODE` supports only `break-before-make`. `PHASE0_ACCESS_LEAVES=4`, `PHASE0_SPINES=2`, and `PHASE0_DAD=baseline` are validated fixed settings. Other values fail explicitly. Make-before-break requires a new dual-interface attachment model with explicit simultaneous-attachment permission, overlap duration, MAC semantics and cleanup tests. DAD configuration sweeps, topology scaling and total active-robot scaling are not implemented. These remain experiment-readiness gaps, not claimed functionality.

**Decision**

PARTIALLY READY for further small, controlled measurement development. The single move correlates all four views and the baseline remains passing. Not ready for large-scale, precise causal latency, DAD or overload experiments. Priorities: capture access-interface ingress and netlink events; improve snapshot cadence/observer overhead; calibrate capture clock relationship; verify ECMP/fallback forwarding from PCAP; add independently repeated runs and workload/topology/DAD controls. No bottleneck, production timing, overload threshold or FRR optimization conclusion is justified.
