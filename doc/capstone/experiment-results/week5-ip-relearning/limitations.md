# Limitations

- Nine fresh runs are exploratory, with one or two runs per treatment, one moving robot, a fixed execution order and no randomized independent order. Seeds 0 and 1 do not change scheduling with one robot. A sample fraction is not a reliable probability for a warehouse fleet.
- Controller probes, baseline priming, router ARP and telemetry mean no experiment is completely traffic-free. One immediate gratuitous ARP is not the same as a gateway ping or ARP reply. Repeated or delayed ARP effects cannot be separated from timing and incidental traffic with these samples. `stimulus-initial.py` is the original worker for the first five runs; final `stimulus.py` adds a gateway branch without changing those branches.
- Phase 0's sequential CLI snapshots are roughly seconds apart, extend the effective schedule and are not atomic. Netlink monitor output is event-driven but not a kernel trace, lacks explicit buffer-loss accounting and is monitored only on Leaf1/2/5. Capture `any` duplicates packets and may miss packets; logs do not certify zero loss. No direct observation identifies every internal BGP, Zebra, FDB, neighbor or packet-drop operation. TCP reassembly and retransmissions are not independently certified. `bgp-nlri-transitions.csv` identifies frame/peer when decoded; it is not a deduplicated route-change count.
- Wall-clock packet and netlink timestamps are from the shared namespace but have no measured error/offset; monotonic command/probe timestamps cannot be precisely mapped to PCAP time. A successful reply after a timeout is a probe-based bound, not an exact interruption length; a failed probe can have delayed delivery and censored runs cannot measure full recovery.
- Network namespaces run on shared host resources. Relevant ARP sysctls, bridge learning configuration and possible kernel-version dependencies require separate controlled verification. Existing code at the current SHA and recorded running binary hashes are available, but the build's exact source linkage was not independently proven. No topology scaling or DAD sweep was performed. DAD samples and neighbor-session snapshots cannot rule out sub-sampling transients; all recorded leaf `show evpn` outputs report enabled 5/180 s. The teammate's diagnostic trace and AP harness were not located; AP behavior is unknown.
- MBB Phase 1 historical comparisons used different stimulus and overlap; no new controlled MBB experiment was run. The data do not establish that a production switch, different kernel, or AP implementation behaves identically, or that this is an FRR defect.
- The first two attempts to run the copied test outside the topotest tree failed during collection/setup (sudo removed PYTHONPATH, then the topotest pytest configuration was not loaded); no topology trial resulted. The successful runs used a temporary copy inside the topotest tree, now removed. `raw-none-01` passed in 45.87 s but its standalone stdout was not saved; other pytest logs are retained.
