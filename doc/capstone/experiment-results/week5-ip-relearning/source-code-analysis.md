| Neighbor notification | `zebra/rt_netlink.c:4550–4700`; `zebra/zebra_vxlan.c:4403–4451` | Netlink neighbor messages are decoded; `is_own` routes to remote-neighbor handling, otherwise to local-neighbor handling. Kernel ARP policies, bridge setup and version can matter; this experiment did not record every relevant sysctl. |
| Local neighbor | `zebra/zebra_evpn_neigh.c:1216–1550` | A local neighbor event can convert remote to local, update sequence, perform DAD checks, and advertise if active and associated MAC local. If MAC is not local, neighbor is marked inactive until a MAC learn. Therefore local MAC alone does not guarantee local IP origination. |
| Advertisement / withdrawal | `zebra/zebra_evpn_neigh.c:224–275`, `:927–987` | Active eligible local neighbor sends `ZEBRA_MACIP_ADD`; inactive/local-neighbor removal or a remote MAC takeover can send deletion. `bgpd/bgp_evpn.c:1675–1735` removes a superseded local route and schedules BGP processing. Exact runtime invocation, timing and per-peer propagation require traces. |
| Protocol | `bgpd/bgp_evpn.c:1183–1275` | BGP sends best remote MAC/IP, VTEP and sequence to Zebra; MAC-only and MAC/IP are separate Type-2 NLRIs. A BGP UPDATE may carry multiple NLRIs; capture copies and retransmissions must not be counted as distinct routes. |

Deletion of the remote IP after old-route withdrawal is visible in the new runs; its trigger cannot be assigned solely from these sampled events. The source and tests do not establish whether the result is intentional or correct for this kernel, emulator, other Linux kernels, or production switches. No FRR source or router configuration was changed.
