# Controller forwarding analysis

The controller is a host behind leaf5; the available Phase 0/1 probe originates there. Leaf5's VRF forwarding state is network reachability, not application-level knowledge of robot location. No controller application location database, updates, or decisions were measured. Phase 0 sampled /32 and /24 routes, source-specific lookup, neighbor/RMAC, VXLAN FDB, final attachment and ICMP; ECMP was present in /24 route snapshots. The lookup and RMAC/FDB mapping suggested leaf3 during one /32-absent sample, then leaf2. These observations are sequential and cannot establish an individual packet's actual path, drop location or atomic state. No exhaustive per-packet correlation or capture-loss accounting is available.

When a /32 points to the old leaf, packets following that state may be delivered to the former VTEP; subsequent forwarding, redirection, flooding or loss depends on its current FDB/neighbor state and is unobserved here. When it points to the new leaf, the route choice agrees with attachment, but success additionally requires correct RMAC, tunnel, bridge and return path. With no /32, a matching /24 can supply longest-prefix fallback; ECMP may select an unrelated leaf. In the cited sample route-get resolved leaf3, but no specific lost packet is tied to it. If the next move occurs before convergence, sampled agreement with a prior attachment can already be stale; this was not tested in available fleet evidence. A timeout does not prove forwarding disagreement, and a successful probe does not prove persistent agreement.

Phase 1 matrix sampled a leaf3 mismatch in 4/5 MBB-100 and 5/5 MBB-500 trials, sometimes without lost probes; route sampling is sparse and query state non-atomic. Absence in a sample does not show a persistent IP relearning failure: later matching forwarding was observed in all 20 matrix trials. It also does not disprove a transient IP-neighbor or Type-2 learning delay. Proving a failure requires controlled traffic, new-leaf ARP/neighbor and Zebra state, MAC/IP route lifecycle, event-based installation and packet tracing on a calibrated timeline.
