**Source-code path reviewed**

Linux bridge FDB/ARP events arrive through netlink. `zebra/rt_netlink.c:4093` parses AF_BRIDGE NEWNEIGH/DELNEIGH into dataplane contexts. `zebra/zebra_vxlan.c:4823` and `:4857` handle local MAC deletion/add/update and map the access bridge to an EVPN instance. `zebra/zebra_evpn_mac.c:2148` maintains local MAC state and notifies clients; `zebra/zebra_evpn_neigh.c` manages associated IP neighbors. Kernel source learning and neighbor discovery are separate observations.

`bgpd/bgp_zebra.c:3600` decodes Zebra MAC/IP notifications. `bgpd/bgp_evpn.c:7934` creates/updates local Type-2 routes; `:7899` removes or reinstalls routes following local deletion. `:2523` builds local routes, `:1463` adds the MAC mobility extended community, `:1740` selects/installs EVPN routes, and `:2777` removes local EVPN routes. EVPN MAC/IP NLRI decoding is in `bgpd/bgp_evpn.c:5284`; serialization is near `:6939`. Received selected remote routes go toward Zebra through `:1185`, then `zebra/zebra_evpn.c:1435` and `zebra/zebra_evpn_mac.c:1997`; remote kernel installation is in `zebra/zebra_evpn_mac.c:185`. BGP UPDATE framing, reception, transmission and timers are in `bgpd/bgp_packet.c`; KEEPALIVE generation is at `:635`. Packet capture observes wire messages, not the internal enqueue/selection instant.

For a remote-to-local move, `zebra/zebra_evpn_mac.c:2286` computes local sequence as `MAX(remote_sequence+1, local_sequence)`. DAD processing in `:469`–`:594` counts moves within the configured window, marks duplicates, optionally freezes advertisement/forwarding updates, and schedules recovery when configured. These are implemented mechanisms; this single move does not exercise the threshold or establish freeze behavior experimentally.
