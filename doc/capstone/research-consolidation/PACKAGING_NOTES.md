# Packaging and exclusions

The archive preserves the selected repository-relative paths for all five experiment-result trees, capstone topology/harness/configuration and historical audit files, selected FRR source files needed to inspect the reported paths, and this consolidation. It includes ignored raw captures and logs. It does not contain the full FRR source tree, installed binaries, unrelated projects, dependency/build caches, Python bytecode, Finder metadata, credentials or the original Phase 1 ZIP as a nested duplicate. A text search for private-key headers, AWS-style access keys and common token assignments in selected text files found no matches; this is a focused check, not a guarantee about every binary payload.

The historical Phase 1 ZIP itself was compared by SHA-256 member content: 3,095 of 3,097 members have byte-identical counterparts in the selected evidence; its two unique files are stored under `historical-review-unique/`. The original ZIP remains outside the package, untouched. Within the selected experiment trees, identical files at distinct original paths are retained when they are part of different trials or necessary to preserve relative links and provenance; their shared hashes in `ARTIFACT_MANIFEST.csv` make them identifiable. They must not be interpreted as independent data merely because they have distinct paths.

`ARTIFACT_MANIFEST.csv` lists each selected source path, byte size, SHA-256, origin and Git status, plus the manifest's self-reference and the explicitly omitted historical ZIP. A file cannot contain its own SHA-256, so the manifest's own row says `SELF`; the archive-root `ARCHIVE_CONTENT_SHA256SUMS` covers it and every other included file, excluding only that checksums file itself. The ZIP cannot include its own hash. `package_research.py` builds a new archive only when its target does not exist, reopens it, checks CRC and every archived file hash, and reports the external ZIP hash. It does not edit original evidence.
